# `reference/` — the 2015 reproduction oracle

This directory holds the outputs of the original build of the dissertation, run
2015-05-15 on Windows 7 under R 3.1.2 with MiKTeX. Nothing here is generated by
the modern toolchain; it is the frozen target that the modern build is measured
against.

It was captured because these files were **untracked** in the original
repository — `.gitignore` excluded `*.pdf` and `*.png`, so 192 figures, the
final PDF, and both knitr caches existed only on the author's disk. One
`git clean` would have destroyed the only evidence of what the correct answer
looks like.

## `2015-build/` — tracked

| Path | What it is |
|---|---|
| `chapters/*/​*.tex` | The five knitr-generated chapter files. **This is the acceptance test.** Every model coefficient, standard error, table, and inline `\Sexpr` number in the dissertation is in here. All five hash-match `v2015-deposit` exactly. |
| `phd_figs/` | All 192 figure outputs (96 pairs of `.pdf` + `.png`). |
| `dissertation.pdf` | The deposited document. 368 pages, 87 figures, pdfTeX 1.40.15, 2015-05-15 02:54:50 EDT. |
| `MANIFEST.sha256` | Checksums over all of the above. Verify with `cd reference/2015-build && sha256sum -c MANIFEST.sha256`. |

The three static chapters (`intro`, `conclusion`, `theoryreview`) are not
copied here — they are hand-written LaTeX under version control already, not
build products. `theoryreview.tex` is not included in `dissertation.tex` at all.

## `2015-knitr-cache/` — not tracked

138 MB of knitr cache from the 2015 run:

- `phd_cache/` — chapter 3, including the 64 MB `chap3-hausmantest` Hausman test
- `chapters/candidacy/cache/` — chapter 3 `modTestDemog`
- `chapters/voterturnout/cache/` — chapter 4 `bootRMSE`, `bootRMSE2` (40 MB each)

These are the chunks the author marked `cache=TRUE` in 2015, which is to say the
expensive stochastic ones: `boot(R=150)`, `PBmodcomp(nsim=200)`, the Hausman
test. They are the **fallback** if a chunk cannot be reproduced bit-exactly on
the modern stack — restoring them makes knitr reuse the 2015 values instead of
recomputing.

Too large to commit, so they live in the archive alongside the raw data. Their
checksums are tracked here as `2015-knitr-cache-MANIFEST.sha256`, so a restored
copy can be proven authentic.

**If any of these caches is ever used to satisfy the build, that fact gets
recorded explicitly in `REPRODUCING.md`.** A reused 2015 number and a
recomputed 2015 number are not the same claim.
